# サービス紹介サイト `/lp`（他塾向け）

つながるまなびを **他塾に紹介するためのサイト**。アプリ本体と同じ Next.js に相乗りしている
（`master` に push すれば Vercel 本番の `https://<本番ドメイン>/lp` で公開される）。

## ファイル

| ファイル | 役割 |
|---|---|
| `src/app/lp/page.tsx` | サイト本体（サーバコンポーネント）。文言・機能一覧はすべてこのファイルの上部の定数にまとまっている |
| `src/app/lp/InquiryForm.tsx` | 問い合わせフォーム（クライアント） |
| `src/app/api/lp/inquiry/route.ts` | 問い合わせの受け口。service role で `saas_inquiries` に書く唯一の口 |
| `lp-inquiries-setup.sql` | 問い合わせテーブル＋RLS |

## 構成（上から順に）

1. ヒーロー … 「生徒・保護者・講師が、同じ画面を見る。」
2. なぜ作ったか … 現場の3つの困りごと
3. 考え方 … ①「何をどこまで」は1か所にだけ書く ②子どもが主役 ③使わない機能は消せる
4. 3つの入口 … 生徒／保護者／講師それぞれに何が見えるか
5. できること … コア機能5つ＋選べる機能8つ（`src/lib/modules.ts` のモジュールと1対1）
6. 塾内経済（AC・自塾株） … 差別化として1画面まるごと
7. 導入の流れ … 4ステップ
8. よくある質問
9. 問い合わせフォーム

> 機能を増減したときは `src/lib/modules.ts` と `page.tsx` の `MODULES` 定数の**両方**を直す。
> （紹介文はマーケ向けに書き分けているので自動生成にしていない）

## セットアップ（初回のみ）

1. **Supabase SQL Editor で `lp-inquiries-setup.sql` を実行**
   - これをやるまで問い合わせ送信は「テーブルが無い」で失敗する。
2. 環境変数
   ```
   SUPABASE_SERVICE_ROLE_KEY=    # 必須（既に設定済みのはず）
   CHATWORK_API_TOKEN=           # 任意。設定すると問い合わせ着信をChatworkに流す
   CHATWORK_INQUIRY_ROOM_ID=     # 任意。上とセットで有効
   ```
   Chatwork の2つが未設定なら通知だけ静かにスキップし、DB への保存は通常どおり動く。

## 問い合わせの見方

いまは Supabase のテーブルエディタで `saas_inquiries` を直接見る。RLS で **admin の講師だけ**が
読める（匿名・保護者・一般講師は読めない）。管理画面が要るようになったら
`/teacher/dashboard` 配下に足す。

- `status`: `new` → `contacted` → `done`（/ `ignored`）
- `interests`: LP でチェックされた関心機能（`modules.ts` の ModuleKey ＋ `core`）

## スパム対策

- ハニーポット（`company_website`。埋まっていたら黙って成功を返して捨てる）
- 同一IPから10分5件までの簡易レート制限（インスタンス内メモリ）
- 各項目の長さ制限・メール形式チェック
- テーブルに INSERT ポリシーを作っていないので、anon キーで直接書き込むことはできない

## トップページ `/` について

`/` はいまも**ログイン入口**（生徒／保護者／講師）のまま。他塾向けの顔を `/` にしたくなったら、
現在の `/` を `/login-select` などへ移し、`src/app/page.tsx` で `/lp` の中身を出す。
既存の生徒・保護者への案内は `/` を前提にしているので、動かすときは周知とセットで。
